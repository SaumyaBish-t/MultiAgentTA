# FORGE Trading System — Data Lineage & Sources

This document tracks the origin of every value displayed in the FORGE Trading Terminal, ensuring zero hardcoded values and full auditability.

## 1. Command Center Dashboard

| UI Element | Backend Source | Database/Cache Key | Lineage |
| :--- | :--- | :--- | :--- |
| **Total Portfolio Value** | Monitoring API (`/status`) | Redis: `portfolio:current:value` | Sum of (Cash + Σ(Positions * Price)) from Phase 6 |
| **Daily P&L %** | Monitoring API (`/status`) | Redis: `portfolio:current:daily_pnl_pct` | Calculated by Phase 6 Portfolio Manager |
| **Active Signals** | Monitoring API (`/status`) | PostgreSQL: `trading_signals` | Count of signals with `status = 'live'` |
| **Market Regime** | Monitoring API (`/status`) | Redis: `research:regime:current` | Detected by Phase 5 Research Agent |
| **Equity Curve** | Monitoring API (`/performance`) | PostgreSQL: `portfolio_performance` | Historical daily snapshots from Phase 7 Audit |
| **System Health** | Monitoring API (`/status`) | Redis: `monitoring:health:latest` | Pulse checks from Phase 8 Health Monitor |

## 2. Strategy Comparison Center

| UI Element | Backend Source | Database/Cache Key | Lineage |
| :--- | :--- | :--- | :--- |
| **Market Price** | Data Ingestion API (`/prices/{t}/history`) | Redis: `prices:cache:{t}` | Real-time Alpaca IEX / YFinance fallback |
| **Strategy Curve** | Monitoring API (`/strategy-comparison/{t}`) | PostgreSQL: `backtest_results.equity_curve` | VectorBT results from Phase 3 Backtesting |
| **AI Hypothesis** | Monitoring API (`/strategy-comparison/{t}`) | PostgreSQL: `research_hypotheses` | Generated by Phase 2 Analyst LLM |
| **Trade Markers** | Monitoring API (`/strategy-comparison/{t}`) | PostgreSQL: `orders` | Filled execution logs from Phase 4 Execution Engine |
| **Alpha / Sharpe** | Monitoring API (`/strategy-comparison/{t}`) | PostgreSQL: `backtest_results` | Risk metrics calculated in Phase 3 |

## 3. Configuration & Infrastructure

- **API Keys**: Managed via `.env` and `config/settings.py`. No keys are hardcoded in source.
- **Service Discovery**: Internal APIs use `settings.internal_api_key` for inter-service communication.
- **Timezone**: All timestamps are UTC-standardized.
